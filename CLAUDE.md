# CLAUDE.md — devops-lab (GitHub-зеркало)

## О проекте
Учебный DevOps-репозиторий для практической подготовки к переходу в DevOps
(рассматриваемые роли: SRE, MLOps, DevSecOps, Platform Engineer).

Метод обучения: ~20% теория / 70% практика / 10% заметки.
Цикл: учу → делаю → ломаю → диагностирую → чиню → коммичу → документирую.

## Репозиторий
Это зеркало основного репозитория проекта (GitLab:
`git@gitlab.com:devops-lab-group9332137/devops-lab.git`), выложенное
на GitHub (`git@github.com:tarnished000/devops-lab.git`) отдельным
проектом-портфолио. CI/CD здесь портирован под GitHub Actions +
GitHub Container Registry (ghcr.io) вместо GitLab CI + GitLab Registry,
потому что GitLab CI на GitHub не выполняется.

- Основная ветка: `main`

## Целевая архитектура (production-like учебный стек)
- Приложение + Nginx + PostgreSQL в контейнерах
- CI/CD + Container Registry (GitLab CI на основном репозитории,
  GitHub Actions здесь)
- ArgoCD → Kubernetes (GitOps-деплой)
- Terraform — инфраструктура (целевое облако: Yandex Cloud)
- Ansible — конфигурация серверов
- Мониторинг: Prometheus + Grafana + Alertmanager

## Текущий прогресс

**Linux** — основы пройдены, практика продолжается по ходу проекта.

**Git** — освоено:
- status / add / commit / push / pull
- ветки, merge
- `.gitignore`
- разрешение merge-конфликтов (осознанно тренировал на `test.txt`)

**Git** — ещё предстоит разобрать:
- stash
- сложные конфликты
- revert / reset
- rebase

**Bash** — ежедневная практика параллельно с остальным стеком.

**Docker / CI-CD / Ansible / K8s / Terraform** — код для всех этапов написан
(по указанному в этом файле порядке), по явному запросу пользователя:
- Docker (`app/`, `docker-compose.yml`) и мониторинг
  (`monitoring/`) — написаны, не запускались вживую в моей среде (нет
  Docker-демона под рукой) — нужно самому прогнать `docker compose up
  --build` и посмотреть, что происходит на практике.
- CI/CD (`.github/workflows/ci.yml`) — написан и портирован под GitHub
  Actions отдельно от `.gitlab-ci.yml` на основном репозитории, так как
  GitLab CI на GitHub не выполняется. См. вкладку Actions за реальным статусом
  последнего прогона.
- Ansible (`ansible/`) — написан, не применялся — реального сервера ещё нет.
- Kubernetes + Argo CD (`k8s/`, `argocd/`) — написаны, не применялись —
  реального кластера ещё нет.
- Terraform (`terraform/`) — написан, не применялся — нужен реальный
  аккаунт Yandex Cloud с оплатой и мой IAM-токен, руками, снаружи.

Подробный статус по каждому этапу — в README.md в корне и в README каждой
папки (ansible/, k8s/, terraform/, monitoring/).

## Как помогать в этом проекте

- Объясняй команды и концепции, а не просто выполняй их за меня — я учусь,
  а не делегирую работу.
- При новой git-теме (stash, revert/reset, rebase) — сначала короткое
  объяснение и безопасный пример на тестовой ветке, потом дай попробовать
  самому, не делай коммиты за меня.
- Где уместно — предлагай сценарии "сломать нарочно и починить": это часть
  моего метода обучения, а не то, чего нужно избегать.
- Двигайся по стеку последовательно: Docker → CI/CD → Ansible → K8s →
  Terraform. Не перескакивай вперёд, если предыдущий этап не закрыт, если я
  сам явно не попросил забежать вперёд.
- Перед действиями с git (push, merge, rebase, force-push) — объясняй, что
  именно произойдёт и обратимо ли это.
